## The signed-out 401s

In the final pass, the **first four signed-out desktop 401s all had the same URL**: `GET https://8080-agq3ndu665es5t4nn6gjyv7wca.instabox.tech/_agent-native/agent-engine/status`. There were ten total repeated 401/console resource errors across the three signed-out pages (five desktop landing, three phone landing, two keyboard landing); **all ten were that exact endpoint**. None was observed in the authenticated pages, and there were no other observed console/page errors. `final-results.json` records the URL for each event.

The installed framework's `use-agent-engine-configured.js` describes this as an **AI-engine readiness probe**, and its `core-routes-plugin.js` status handler resolves request identity; the auth guard rejects unauthenticated internal routes. Thus a 401 is the expected response to this signed-out readiness probe, not a failed login and not the auth/session endpoint. Repeated probes still make the console noisy. The _earlier_ four errors in `verification-run1.md` have no retained URLs, so it is reasonable but **not provable** that they were the same requests.
