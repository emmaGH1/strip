## Findings

- **FAIL — requested clean composer:** select `[data-testid="comic-canvas"] [data-object="balloon-1"]` → Ask agent → Funnier → Send to agent. The no-provider setup prefill shows `Funnier`, not internal instructions in the message text, but the visible composer also contains context chips **`Panel 1: balloon-1`** and **`Ari's line · revision 1`**. Thus it does not show only Funnier/no IDs. See `composer.png`. This is a setup prefill, not a submitted AI turn. The panel-ID chip was already present immediately after selection (`context-placement.png`).
- **PASS, bounded placement:** at this viewport and balloon selection, `.desktop-context .context-bar` bottom y=179 and `[data-testid="comic-canvas"]` top y=191: 12 CSS px gap outside the page. `context-placement.png`. No general claim for all selections or phone.
- **PASS — authenticated MCP / live Library:** the signed-in user's framework `/mcp/connect/token` minted a per-user full-catalog bearer. A script performed actual JSON-RPC MCP `initialize`, `tools/list`, and `tools/call` to `/mcp`; `create-strip` used the complete externally supplied illustrative fixture. Library remained on `/home` and displayed the new “Illustrative MCP transport test two” without navigation or refresh. Compare `library-before.png` and `library-after.png`: the prior first test record already existed, and the before capture caught its thumbnail before rendering. Both records belong to this test account. To obtain a real minted token rather than loopback dev-open's empty token, the local request used forwarded host/proto matching the app's configured public issuer; the MCP requests themselves went to loopback. Full-catalog was needed: the default catalog did not expose `create-strip` directly.
- **PASS — live Studio update:** MCP `get-strip` returned revision 0; MCP `update-strip` changed balloon 1. The already-open Studio showed the new line and Rev 1 without reload (`studio-after-mcp.png`).
- **PASS — History / restore:** in the real Agent changes footer, History showed Rev 1 and Rev 0 as External agent; Restore on Rev 0 produced Rev 2 · You, “Restored revision 0”, with original line on the page and prior entries retained (`history-before-restore.png`, `history-after-restore.png`). The restored scene visibly changed from all-blue to ink and Agent changes fell from 13 to 0; this is an observation, not a judgment of intended restore attribution semantics.
- **PASS — bounded safety:** human protected the test balloon in Studio (`protected.png`), then MCP update at current Rev 3 returned `protected_element`; MCP write with expectedRevision 0 returned `stale_revision`. A fresh MCP get confirmed unchanged revision and protected balloon text. Unauthenticated MCP `tools/list` returned HTTP 401. MCP `get-strip` for a fabricated nonexistent UUID returned `not_found`. This does **not** prove cross-user isolation because no second account or other user's record was accessed; agent unlock and concurrent writes were not exercised here.

The script used direct JSON-RPC over the real MCP HTTP transport, not the regular action endpoint; it was an ephemeral test script and is not retained as a reusable credential-bearing fixture.
